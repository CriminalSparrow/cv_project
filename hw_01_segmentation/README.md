# Background Removal in Real Time

ДЗ №1: сегментация человека и замена фона в видеопотоке на CPU.

## Выбранное решение

Используется [MediaPipe Selfie Segmentation](https://chuoling.github.io/mediapipe/solutions/selfie_segmentation.html)
через [Image Segmenter API](https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter/python).
Это лёгкая свёрточная сеть на основе MobileNetV3, предназначенная для видеозвонков
и выделения людей, расположенных близко к камере. Обучать её не требуется.

Выбрана обычная модель Selfie Segmenter с входом 256×256 и весами float16.
MediaPipe сам преобразует RGB-кадр во вход модели и возвращает маску в разрешении кадра.
На выходе один канал: вероятность принадлежности пикселя переднему плану.
Инференс запускается с `Delegate.CPU`, используется TensorFlow Lite / XNNPACK.
OpenCV также работает на CPU. CUDA и отдельная видеокарта не нужны.

Модель небольшая (около 244 КиБ), рассчитана на интерактивную обработку и не требует
подсказок пользователя. Для этой задачи она проще и дешевле по вычислениям, чем SAM.
Файл весов включён в `models/`.

Пайплайн: захват кадра → изменение размера → BGR в RGB → модель → сглаживание маски
→ смешивание с фоном → показ. Модель вызывается на **каждом** кадре, пропуска инференса нет.

Маска слегка размывается фильтром 5×5. Вероятности от 0.25 до 0.75 линейно переводятся
в диапазон 0–1, остальные обрезаются. Затем добавляется 25% предыдущей маски, чтобы
уменьшить мерцание. Итоговый кадр: `alpha * frame + (1 - alpha) * background`.

## Установка

Нужен **Python 3.11**, 64-битная система и веб-камера либо видеофайл.
Проверено на Python 3.11.9, macOS 27.0.1, Apple Silicon.
Windows/Linux команды приведены ниже, но на этих системах решение не проверялось.

Откройте терминал в корне репозитория и переключитесь на ветку `hw_01_segmentation`.
Далее все команды выполняются из папки `hw_01_segmentation`.

macOS / Linux:

```bash
cd hw_01_segmentation
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows, PowerShell:

```powershell
cd hw_01_segmentation
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию, можно без неё вызвать
`.\.venv\Scripts\python.exe -m pip install -r requirements.txt`, а затем
`.\.venv\Scripts\python.exe main.py --compare`.

## Запуск

Камера, зелёный фон, слева исходный кадр, справа результат:

```bash
python main.py --camera 0 --width 640 --height 480 --mode color --compare
```

Другие режимы:

```bash
python main.py --mode blur --compare
python main.py --mode color --color 40,80,160 --compare
python main.py --mode image --background background.jpg --compare
python main.py --video input.mp4 --mode blur --compare
```

В режиме `image` нужен свой файл изображения. Он масштабируется и обрезается по центру
без изменения пропорций. Кадры источника приводятся к `--width × --height`; для видео
16:9 лучше указать, например, `--width 640 --height 360`, чтобы не растягивать изображение.
Кадр камеры зеркально отражается, как в обычном предпросмотре видеозвонка; файл не отражается.

Выход — **Q**, **Esc** или закрытие окна. После выхода статистика записывается
в `results/local.json` и выводится в терминал. Следующий запуск перезапишет этот файл;
для отдельного отчёта используйте `--report results/local_camera.json`.

| Параметр | Значение по умолчанию / назначение |
| --- | --- |
| `--camera` | `0`, индекс камеры; если выбрана не та камера, попробуйте `1` |
| `--video` | путь к видео вместо камеры |
| `--width`, `--height` | `640`, `480`, разрешение обработки |
| `--mode` | `color`, также доступны `blur` и `image` |
| `--color` | `80,160,80`, цвет в порядке RGB |
| `--background` | путь к изображению для `--mode image` |
| `--smoothing` | `0.25`, доля предыдущей маски; `0` отключает сглаживание во времени |
| `--compare` | показать оригинал рядом с результатом |
| `--headless` | без окна; видео обрабатывается без задержек воспроизведения |
| `--frames` | остановиться после указанного числа измеряемых кадров; без него — до выхода/конца файла |
| `--report` | `results/local.json`, путь к JSON со статистикой |

Полный список: `python main.py --help`.

## Измерение производительности

Время измеряется через `time.perf_counter()`. Первые 10 кадров — прогрев, они
исключены из статистики. Кадр учитывается только после сегментации и композитинга.

- **Processing FPS** = число обработанных кадров / суммарное время их обработки.
  Включает изменение размера, отражение, преобразование цвета, инференс, обработку
  маски, подготовку фона и композитинг. Не включает чтение камеры/файла, текст и окно.
- **Loop FPS** = то же число кадров / время полного цикла. Дополнительно включает
  чтение источника, подготовку сравнения, показ окна и ожидание следующего кадра.
- **Latency** — среднее и 95-й перцентиль времени обработки кадра, без захвата и показа.

В окне показатели усредняются по последним 30 измеряемым кадрам; итоговый JSON
считается по всем измеряемым кадрам. Среднее от значений `1 / latency` не используется.
Видео в окне воспроизводится с исходной частотой, если обработка успевает.
Поэтому для файла 10 FPS показатель Loop FPS в окне будет около 10 даже на быстром CPU.

### Результаты

Замер **Apple M3 Pro**, macOS 27.0.1 arm64, Python 3.11.9.
CPU delegate, OpenCV — 1 поток. Вход: первые 310 кадров публичного
[vtest.avi из OpenCV 4.11.0](https://raw.githubusercontent.com/opencv/opencv/4.11.0/samples/data/vtest.avi),
768×576, 10 FPS. Обработка: **640×480**, 300 измеряемых кадров после 10 кадров прогрева.
Режим `--headless`, чтение файла без ограничения скорости. Каждый режим запускался отдельно.

| Фон | Processing FPS | Средняя latency, мс | p95, мс | Loop FPS без окна |
| --- | ---: | ---: | ---: | ---: |
| Цвет | 115.8 | 8.64 | 10.12 | 107.5 |
| Размытие | 108.5 | 9.22 | 10.16 | 101.1 |

Исходные результаты: [цвет](results/benchmark_color.json), [размытие](results/benchmark_blur.json).
Это короткий замер скорости пайплайна на файле, **не измерение FPS веб-камеры**.

Повторить замер (macOS/Linux; в PowerShell вместо `curl` можно использовать `curl.exe`):

```bash
curl -L --fail https://raw.githubusercontent.com/opencv/opencv/4.11.0/samples/data/vtest.avi -o vtest.avi
python main.py --video vtest.avi --headless --frames 300 --report results/local_color.json
python main.py --video vtest.avi --mode blur --headless --frames 300 --report results/local_blur.json
```
Тестовое видео не включено в репозиторий.

Замер с камерой и окном:

```bash
python main.py --camera 0 --compare --frames 600 --report results/local_camera.json
```
processing_fps - 93, loop_fps - 28

### Качество

Визуально проверено на публичном
[тестовом изображении MediaPipe](https://storage.googleapis.com/mediapipe-assets/segmentation_input_rotation0.jpg)
с несколькими людьми и лошадью. Люди выделяются, крупные участки фона убираются,
на краях остаются переходные пиксели. Часть лошади ошибочно попадает в передний план.
Следовательно, модель не гарантирует удаление всех посторонних объектов.

Модель рассчитана прежде всего на человека рядом с камерой. Далёкие люди, мелкие
детали, волосы, предметы в руках и плохое освещение — сложные случаи. `vtest.avi`
с далёкими пешеходами использован для замера скорости, а не как показатель качества
видеозвонка. Сглаживание уменьшает дрожание маски, но при быстрых движениях может
оставлять короткий след; тогда можно уменьшить `--smoothing` до `0.1` или `0`.


Качество и устойчивость на собственной веб-камере:
по моим оценкам вполне приемлемо, хоть и артефакты вокруг головы бросаются в глаза.
